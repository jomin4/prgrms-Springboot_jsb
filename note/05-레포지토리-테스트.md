# 05단원: 레포지토리 + 테스트 (JpaRepository)

## 🧠 머릿속 그림 요약
`QuestionRepository`는 **인터페이스**로 `JpaRepository<Question, Integer>`만 상속. 구현 코드 0줄. Spring Data JPA가 실행 시점에 **구현체(프록시)를 자동 생성**해 컨테이너에 등록 → `@Autowired`로 주입받아 `save/findAll/findById`를 바로 사용. 각 메서드는 INSERT/SELECT SQL로 실행된다.

## 📌 핵심 내용
- **JpaRepository<엔티티, 기본키타입>**: `<Question, Integer>` = Question을 id(Integer)로 다룸. save/findAll/findById/delete/count 등 기본 CRUD 제공.
- **인터페이스인데 동작하는 이유**: Spring Data JPA가 런타임에 프록시 구현체 자동 생성·주입.
- **Lombok @Getter/@Setter**: 엔티티 필드의 접근자를 컴파일 시 자동 생성(테스트에서 set/get 사용).
- **바인딩 순서 = 컬럼 순서**: content(1)→create_date(2)→subject(3). id는 IDENTITY라 바인딩 대상 아님.

## 🔎 디버깅 정리 (실제 값)
- 실행: `./gradlew test --tests QuestionRepositoryTest` → **PASSED**, BUILD SUCCESSFUL.
- test 프로필(메모리 H2)이라 매 실행 깨끗한 DB에서 시작 → findAll 결과 정확히 2건.
- q1 저장 시 바인딩 TRACE 로그:
  ```
  binding parameter (1:VARCHAR)   <- [sbb에 대해서 알고 싶습니다.]   (content)
  binding parameter (2:TIMESTAMP) <- [2026-08-19T15:14:39.870...]   (create_date)
  binding parameter (3:VARCHAR)   <- [sbb가 무엇인가요?]             (subject)
  ```
- 단건 조회 시: `binding parameter (1:INTEGER) <- [1]` (findById(1)).

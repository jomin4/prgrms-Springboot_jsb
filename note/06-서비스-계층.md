# 06단원: 서비스 계층 (@Service, DI)

## 🧠 머릿속 그림 요약
계층 분리: Controller → Service → Repository → DB. 각 층은 바로 아래 층만 호출한다. 이번 단원은 중간의 **Service** 계층을 추가. `@Service` 빈이 비즈니스 로직(getList, getQuestion)을 담당하고, `@RequiredArgsConstructor`로 레포지토리를 생성자 주입받는다.

## 📌 핵심 내용
- **왜 계층 분리?** 관심사 분리 / 재사용 / 트랜잭션 경계 / 테스트 용이.
- **@Service**: 비즈니스 로직 빈. 컴포넌트 스캔으로 자동 등록.
- **@RequiredArgsConstructor + private final**: Lombok이 final 필드 받는 생성자를 생성 → 스프링이 그 자리에 빈 자동 주입(생성자 주입 DI). `new` 불필요.
- **getQuestion 분기**: `findById(id)`가 `Optional<Question>` 반환 → 있으면 반환, 없으면 `DataNotFoundException` throw.
- **DataNotFoundException**: `@ResponseStatus(HttpStatus.NOT_FOUND)` → 웹 요청 중 터지면 HTTP 404 자동 응답(지금은 테스트에서 예외 타입만 확인).

## 🔎 디버깅 정리 (실제 값)
